```release-note:internal
Added a provider version-ladder test harness (internal/acctest/upgradeladder, `make testupgradeacc`) that applies each participating resource's configuration across released provider versions — from the oldest release supporting the current PingFederate server version through the local build — and asserts an empty plan after every version hop, catching "Provider produced inconsistent result after apply" bugs that only surface on provider version changes (CDI-532, CDI-533). Resources opt in with a small test in their existing `*_gen_test.go` reusing their generated HCL; ladder tests compile everywhere but run only under the `upgradeladder` build tag (i.e. `make testupgradeacc`). The 12.2–13.1 lane table and ladder derivation live in the harness and are tied to `internal/version`. The harness's first full-lane run caught a real released-provider defect — v1.3.0–v1.4.4 pingfederate_incoming_proxy_settings plan-default asymmetry (bug fix in PR #494, released v1.4.5) — which the ladder encodes via that resource's AvailableSince pin. In CI the ladder runs only post-merge and in the weekly scheduled workflow.
```
